About this explorer

Explore logical architecture options for query-side search pipelines

This full-page tool makes the query side of a modern search system visible and discussable. It maps the logical stages between receiving a query and assembling a response: understanding and constraints, retrieval legs, fusion, reranking, policy, recovery, presentation, and the control or feedback paths that support them. Use it to compare sensible pipeline shapes, expose dependencies and trade-offs, and decide which capabilities earn a place in the request path.

What the tool offers

The explorer combines an interactive architecture map with implementation guidance and component-level design notes.

Progressive reference templates

Move from a locked Core baseline, through the recommended production target, to the Full surface of specialised options. Each level reveals the additions it makes.

Composable pipeline variants

Switch non-core components on or off to test a pipeline shape. The sidebar updates estimated p95 latency, build-and-run complexity, request-path model count, and capability coverage.

Query-facet and capability tracing

Use the worked query to follow a hard constraint, subjective need, text attribute, or visual attribute through the stages that handle it. Select a capability to see its contributing components.

Component design detail

Open any node for its purpose, decisions, defaults, inputs and outputs, failure modes, tuning dials, dependencies, implementation notes, and supporting references.

Request-time and offline relationships

Connections show how data and candidates flow, while distinct control and training wires separate request-time steering from offline learning and feedback.

Evidence-gated build order

The Build order view sequences work by value for cost. Each step names the trigger to begin, what it buys, and the concrete slice to build—rather than pretending every system needs every stage.

How to use it well

Treat the explorer as a structured design conversation, then validate its hypotheses with your own queries, corpus, relevance judgements, and production constraints.

Start with Core

Learn the minimum end-to-end path first. Open each component and make sure its contract, owner, and observable outcome are clear for your system.

Use the worked query to test responsibility

Trace its facets and ask where each signal is extracted, retrieved, scored, enforced, and explained. Missing or duplicated responsibility usually reveals an architecture gap.

Advance to Core + recommended

Review the newly added stages as a likely production target. Toggle alternatives deliberately and watch the comparative budget and capability effects.

Let evidence unlock complexity

Use Build order triggers and evaluation failures to justify the next addition. Visit Full surface only for options tied to a demonstrated recall, ranking, modality, policy, or scale problem.

Record the resulting design

Capture the chosen stages, boundaries, assumptions, degradation order, latency allocation, and evaluation plan. The useful output is the reasoning behind a pipeline—not the diagram alone.

Interpretation guardrail. This is a logical architecture explorer, not a vendor recommendation, deployment topology, capacity model, or guaranteed latency calculator. The estimates are comparative prompts; benchmark the selected design against your own traffic, index, hardware, models, and quality targets.
